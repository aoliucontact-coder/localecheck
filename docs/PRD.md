# LocaleCheck 第一版需求

## 用户与问题

用户：准备推出英文产品的中文独立开发者和小团队。
场景：上线前批量审查按钮、菜单、提示、错误及订阅文案。
问题假设：直接翻译后仍有术语不一致、数字错误、语境误判；需访谈验证。

## 第一里程碑

用 examples/ui-copy.csv 的十条合成文案走通导入、审校、人工确认、导出。

## 输入

UTF-8 CSV，必填列 id、source、target，可选 context。id 必须非空且唯一。
项目背景包含产品说明、目标受众、语气；术语表包含中文术语与指定英文。
首版建议最多 100 条；空译文提示漏译。错误文件应给出清晰原因，不静默丢弃行。

## 审校输出

每条建议包含文案 id、类别、严重程度、原文依据、原译文、建议译文和中文理由。
类别：准确性、完整性、术语、数字、占位符、语境、可选风格。
状态：待确认、接受、拒绝、需要补充语境。
风格偏好不得自动标成错误；信息不足时提示补充语境。

## 人工确认与导出

逐条接受或拒绝；未接受的建议不得覆盖原译文。
导出保留原始 id、source、context 和确认后的 target。
处理 CSV 引号、逗号、换行及电子表格公式注入风险。

## 验收

- 十条样例均能导入并保持顺序和 id。
- 数字与占位符变化有明确证据，正常文案不必生成建议。
- 接受建议仅修改指定条目，拒绝或未处理保留原译文。
- 导出后重新导入不丢失文案内容。
- 模型失败时保留输入和人工决定，允许重试；不能伪造成功。
- 演示数据与真实模型输出明确区分。
- API 密钥仅在服务端使用，不进入仓库、前端或日志。

## 本版范围之外

多语言、网页抓取、复杂文件格式、支付、团队权限和全自动发布。
