# LocaleCheck 用户研究执行目录

本目录用于执行路线图第二周的目标用户访谈。所有模板都要求区分用户原话、观察事实、研究者解释和后续假设，防止把礼貌性赞同或研究者推测当成需求证据。

## 目标

- 完成 5 位目标用户访谈；
- 至少 3 位受访者在最近三个月处理过英文产品文案；
- 至少 2 位愿意提供脱敏材料或参与真实任务试用；
- 判断是否至少 3/5 用户独立提到同一种高频或高风险问题。

## 执行顺序

1. 使用 [招募与筛选](RECRUITMENT.md) 寻找候选人并判断是否符合目标用户条件。
2. 为每位受访者复制一份 [访谈记录模板](INTERVIEW-NOTE-TEMPLATE.md)，文件名使用匿名编号，例如 `P01.md`。
3. 访谈结束当天整理记录，不凭记忆补写用户原话。
4. 完成至少 3 份访谈后开始填写 [证据综合表](SYNTHESIS.md)。
5. 5 份访谈完成后，依据预先定义的门槛作出“保持定位、调整定位或证据不足”的决定。

## 隐私规则

- 不在仓库中记录姓名、邮箱、微信、公司内部项目名或其他直接身份信息。
- 使用 `P01`、`P02` 等匿名编号。
- 用户原始文件默认不进入公开仓库；只保留获得许可的脱敏片段。
- 删除令牌、内部 URL、客户名称、账号、商业数据和未公开功能信息。
- 录音或录屏前必须单独征得同意；不同意时只做文字记录。
- “同意访谈”不等于“同意公开材料”，两项许可必须分开记录。
- 无法确认是否可以公开的内容一律不提交。

## 证据状态

每条发现只允许使用以下状态：

- `observed`：访谈中直接观察到的行为或用户展示的真实流程；
- `quoted`：能够准确追溯到记录的用户原话；
- `reported`：用户描述的历史行为或问题，但没有现场观察；
- `inferred`：研究者基于多条证据作出的解释；
- `hypothesis`：尚待验证的产品假设。

只有 `observed`、`quoted` 和 `reported` 可以计入用户证据数量；`inferred` 和 `hypothesis` 不得用于宣称需求已经验证。
