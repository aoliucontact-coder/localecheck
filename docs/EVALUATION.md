# 评测计划

尚无实测结果。examples 中均为自行构造的合成案例，不能当作真实用户证据。

建立约 80—100 条案例，覆盖误译、漏译、术语、数字、占位符、语境不足、可选润色和正确译文。每条人工标注问题类别、依据、严重程度以及可接受修订；不要求只有一种正确译文。

调试集与留出测试集分离。最终测试集不得用于修改提示词。保存模型标识、提示词版本、配置和运行日期以支持复核。

基线：相同模型直接审校相同文本。产品方案：相同模型配合上下文、术语、规则和人工确认。对比时记录额外输入，避免将不同信息条件误当作纯模型能力差异。

指标：问题级精确率与召回率、每百条正确文案误报数、建议采纳率、完成审校耗时、漏检数、响应耗时及费用。零分母标为不适用；报告样本量和计数。

用户测试采用难度相当的不同材料并交换使用顺序，减少重复阅读熟悉效应。模型自评仅作辅助；人工审校结果作为参考，有条件时请第二位审校者复核争议。

## 当前评测管线

仓库包含 `evals/rules.dev.json`，这是 32 条合成案例组成的规则开发集，仅用于验证确定性检查与指标计算是否可重复运行。它不是冻结测试集，也不是真实用户材料。

运行：

```bash
pnpm eval:rules
```

输出包括案例数、问题级 TP/FP/FN、精确率、召回率、F1、正确案例数量、每 100 条正确案例误报数和分类计数。零分母输出 `null`，表示不适用，不按 0 分处理。

运行评测前会验证数据集元数据、来源类型、开发/测试分组、案例字段、唯一 ID、术语表和允许的问题标签。重复 ID、重复标签、未知标签和重复中文术语会导致评测直接失败，防止损坏的数据产生看似有效的指标。

正式评测仍需补充真实或脱敏案例、第二位标注者复核以及与开发集隔离的冻结测试集。不得根据当前合成开发集结果宣称产品提高了真实翻译质量。
